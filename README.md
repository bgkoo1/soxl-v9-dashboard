# SOXL V12 Final · Quant Dashboard

V12 명세 1.0의 독립 엔진과 Streamlit 운용 대시보드입니다.
공식 진입점은 `streamlit_app.py`입니다. 이전 대시보드 진입점도 새 앱을 실행합니다.
새 앱은 이전 전략 엔진·대시보드를 불러오지 않습니다.

## 실행과 배포

```bash
python -m pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

Streamlit Community Cloud: 저장소 `bgkoo1/soxl-v9-dashboard`,
이 변경이 포함된 브랜치, Main file path `streamlit_app.py`, Python 3.12.
App settings의 Secrets에 아래 항목을 설정합니다. 실제 값은 코드에 넣지 않습니다.

```toml
DASHBOARD_PASSWORD = "운용자가 직접 정하는 긴 비밀번호"
GITHUB_REPO = "bgkoo1/soxl-v9-dashboard"
GITHUB_BRANCH = "main"
GITHUB_TOKEN = "해당 저장소 contents 읽기/쓰기 토큰"
PORTFOLIO_ENCRYPTION_KEY = "기존 V12 원장과 동일한 Fernet 키"
# 아래 메리츠 항목은 기존 값을 그대로 유지합니다.
MERITZ_APP_KEY = "기존 메리츠 앱키"
MERITZ_APP_SECRET = "기존 메리츠 앱시크릿"
MERITZ_MAC_ADDRESS = "기존 12자리 MAC 주소"
```

실계좌 또는 저장 토큰 설정 시 로그인 후 화면을 엽니다. Community Cloud의
앱 접근 권한도 운용 목적에 맞게 설정하세요. 원장 `v12_manual_holdings.enc`는
기존 암호화 형식과 SHA 충돌 검사를 유지합니다. 읽기·복호화 오류 시 빈 원장으로
덮어쓰지 않습니다. Secrets가 없으면 빈 세션 모드로 실행합니다.
첫 화면은 메리츠 실계좌 운용 데스크입니다. 인증 설정이 없어도 연결 메뉴와
누락 설정을 표시하며 금액을 0으로 꾸며 표시하지 않습니다. 수동 원장 모드의
USD 예수금·평가환율만 직접 입력하며, 세션에서 유지됩니다.

## 메리츠 실계좌 기준 운용

로그인 후 예수금·주문가능금액·해외 잔고·체결 상세·입출금 거래내역과 SOXL 시세를 조회합니다.
화면이 열린 동안 SOXL 시세 15초, 잔고·예수금 30초, 체결 60초 간격으로
각각 다시 읽고 사이드바에서 즉시 새로고침할 수 있습니다. 각 연결은 독립적이므로
체결 조회 실패가 정상 조회된 계좌·시세 화면을 지우지 않습니다. 실패한 연결의
마지막 정상값은 조회시각과 함께 참고용으로 남기며 주문계획에는 사용하지 않습니다.
메리츠 실시간 시세 요청이 거절되면 지연시세로 재시도하고 `지연시세`를 표시합니다.
정규장·주간거래·애프터장 최근가를 구분합니다. 시각은 조회시각이며 거래소 체결시각은
해당 시세 응답에 없어 표시하지 않습니다. 틱 단위 스트리밍은 아닙니다.
브라우저가 닫힌 동안의 백그라운드 수집·웹소켓 실시간 수신은 구현하지 않았습니다.
다시 접속하면 조회 기간의 체결을 모두 다시 읽어 현재 잔고와 대조합니다.

1. 사이드바의 `운용 화면 → 메리츠 실계좌`를 선택합니다(기본값).
2. 체결 이력 조회 시작일을 설정합니다. 이전 매수분이 있으면 `계좌 개설 이후 전체 이력 조회`를 선택합니다.
3. 메리츠 체결내역의 표시 시간대를 선택합니다. 미국 거래일로 변환해 D0·D2·D7을 계산합니다.
4. SOXL 수량 대조 결과와 거래내역을 확인합니다.
5. 신규매수 수량이 필요하면 `V12 매수 배정 기준 → 전일 확정 V12 NAV ($)`를 입력합니다.

상단에는 SOXL 현재가·USD 예수금·USD 주문가능금액·SOXL 보유수량·평가손익을 표시합니다.
그 아래에는 V12 다음 행동, 날짜별 매수·매도 실제 체결, 슬롯별 진입가·LOC 목표가·
목표까지의 거리·D2/D7/MOC 행동을 보여줍니다. 연구·수동 원장은 별도 화면입니다.
SOXL 시세 시장 코드는 기본 AX이며 계좌 시세 분류에 따라 `계좌·체결 설정`에서
NY/OQ를 선택할 수 있습니다. 응답 종목·통화·양수 가격을 검증하며 0 가격은 거부합니다.

현재 예수금·장중 평가액만으로 전일 확정 NAV를 확정할 수 없어 이 값은 직접
확인합니다. NAV/6 전략자산은 V12에 배정한 USD 현금과 SOXL 기준이며, 다른
종목의 평가액을 자동 편입하지 않습니다. 매수 재원은 현재 USD 예수금과
주문가능금액의 보수적 한도로 제한하고 당일 매도·재매매 가능 금액을 제외합니다.
예수금 반영 시점 때문에 이 한도는 실제 가용액보다 작을 수 있습니다.

같은 매수 주문의 부분체결을 한 슬롯으로 합칩니다. 실제 매도는 FIFO로 잔여
매수분에 배분하며, 이는 증권사의 세무상 매입분 지정과 같다는 뜻이 아닙니다.
조회 이력 부족·입출고·분할/병합·미체결·매도가능수량 부족이 있거나 복원 수량이
잔고와 다르면 주문계획을 보류합니다. 계좌 잔고·거래내역은 계속 확인할 수 있습니다.
예약주문 전체의 부재를 보증하지 않으므로 실제 주문 전 증권사 주문 화면을 확인합니다.

계좌 원본·토큰은 인증된 사용자 세션에만 보관하며 GitHub에 저장하지 않습니다.
수동 원장과 자동 체결을 합산하지 않고 데이터 기준을 전환합니다.
새 조회가 실패하면 이전 정상 자료를 최신 운용값으로 사용하지 않습니다.
체결번호가 0으로 내려오는 주문 이력은 상세 조회에서 실제 체결번호를 확인하고
중복 제거합니다. 모든 연속조회 키는 공백까지 보존합니다.

조회 전용 REST 명세 출처:
[메리츠 공식 API 문서](https://openapi.imeritz.com/apiservice),
[메리츠 공식 API 카탈로그와 보정 안내](https://github.com/meritz-securities/open-api-mcp/tree/main/meritz/data).
증권사 주문·정정·취소·환전 요청은 전송하지 않습니다.

## 화면

- 오늘의 주문계획: 매도 우선순위, 매수 예산·참고수량, CSV.
- 실제 보유·체결: 실계좌 자동 반영 또는 수동 원장의 매수·부분매도·취소·복구.
- 매매일지·입출금: 메리츠 체결 상세·거래내역 또는 별도 수동 원장.
- 백테스트: USD NAV, 낙폭, CAGR·MDD, 거래 기록.
- 전략·연결 상태: 고정 규칙과 메리츠 조회 전용 잔고 대조.

## V12 Final 1.0 규칙

- 최대 6슬롯, 전일 확정 NAV/6, 별도 강제 현금유보 없음.
- 기본 1슬롯 MOC + 전일 종가×0.91 급락 LOC 추가 1슬롯.
- D0=매수일. D2 종가 수익률≤−10% → D3 개별 MOC.
- D2 손절 발생 AND 해당일 Vol20≥0.10 → 신호일 보유 전 슬롯 다음 거래일 MOC.
- Vol20: 20개 일별 로그수익률 표본표준편차(ddof=1), 비연환산.
- 청산 순서: 전체 MOC → D2 개별 MOC → D7 MOC → 진입가×1.032 LOC.
- Risk B: 전일 MA200 괴리율<−15% AND −20%≤20일 모멘텀<−5%.
- Risk B 또는 직전 4거래일 이상 연속 하락이면 신규매수 중단. TB3 OFF.
- 당일 매도대금은 당일 매수 재원에서 제외.

연구는 USD 자본·USD 조정종가·소수점 수량·종가 전량 체결을 가정하며
비용·슬리피지를 미반영합니다. 첫 진입 전에 MA200 준비 기간을 요구합니다.
실제 원장과 연구 수익률은 별도입니다. 이전 엔진의 청산 순서를 수정했으므로
과거에 보고된 CAGR·MDD 수치를 강제로 재현하지 않습니다.

실제 신호는 입력한 체결가와 조정종가로 계산합니다. 분할·병합 전 명목 체결가를
그대로 입력하면 가격 기준이 달라지므로 기업행동이 있던 보유분은 별도로 대조해야 합니다.
실계좌 모드는 조회 기간 내 주문·미체결·부분체결을 다음 조회 때 반영합니다.
수동 원장은 실제 매도를 입력하기 전까지 대기로 남습니다. 매수 계획은 예정 매도 슬롯을 미리 비우지
않으며 MOC 참고수량은 확정 종가 기준 추정치입니다.

NYSE 캘린더로 확정 종가일·다음 주문일을 계산합니다. 가격이 지연되면 주문계획을
숨깁니다. GitHub Actions는 평일 한국시간 08:35·09:35 업데이트를 시도합니다.
GitHub 스케줄 지연에 대비해 화면의 데이터 기준일을 확인하세요.
